Claude Desktop

Skills only reach Claude Code, because a skill is instructions and Claude Code is what can read your disk. Claude Desktop reaches the brain a different way: it launches a small server on this machine that reads brain/ directly. Nothing is hosted, nothing is exposed, and your notes never leave this disk.

Paste this into {{ desktop_config_paths.macOS }} (on Windows, {{ desktop_config_paths.Windows }}), or open Claude Desktop → Developer → Edit Config. Every path is already filled in for this machine.

If it doesn't appear

Run the same command in a terminal. Claude Desktop only surfaces a failed launch in its logs, whereas here the error prints straight out: 

{{ desktop.command_line }}

It should print one serving brain at … line to stderr and then wait — that silence is the server holding the protocol channel open. Ctrl+C to stop. An import error or a wrong path shows up immediately instead.

What each one does

mind-reader

The retrieval protocol. It loads your identity core on every task, reads INDEX.md to decide what else is worth opening, and pulls a handful of files rather than the whole repo. It is bound by the rules that keep it honest on your behalf: never quote a private note, never present a superseded take as your current position, and never state numbers from a project card that has gone more than 45 days unverified.

mind-feeder

The writer, and the only one. It extracts two to four notes from a source, insists on a verbatim quote of your actual words in every take and story, and proposes everything for your approval before a single file is written. A brain that fills itself with unreviewed extractions is one you stop trusting — so it does not get to.

Trying it

In Claude Code, open any project and ask for something in your voice — “draft a post about X as me”, or “what's my take on Y”. The reader triggers on its own. To feed something in, say “add this to my brain”.

In Claude Desktop, ask the same things. The server is read-only, so Desktop can draw on your brain but cannot change it — adding notes stays here, where you see the change before it lands.
